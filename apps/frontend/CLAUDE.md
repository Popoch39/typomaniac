# apps/frontend

Front React 19 + Vite 8 (React Compiler Rust d'Oxc via `react({ compiler })` de `@vitejs/plugin-react`, pas de Babel). Point d'entrée : `src/main.tsx`.

## Skill obligatoire

**Avant de créer, modifier ou relire un composant, un hook ou tout code React**, invoquer le skill `vercel-react-best-practices` et appliquer ses règles. Pas d'exception pour les petites modifications.

## Architecture

- **Routing** : TanStack Router en file-based (`src/routes/`, plugin Vite, `autoCodeSplitting`). `src/routeTree.gen.ts` est généré (ignoré par oxlint/oxfmt), ne pas l'éditer. Un fichier de route ne déclare que `Route` ; ses composants vivent dans `src/pages/` (sinon `react/only-export-components` casse, et exporter le composant depuis la route désactive le code-splitting). Le routeur vient de la fabrique `createAppRouter` (`src/app-router.ts` : historique, stockage de la Locale, langues du navigateur, `queryClient`) : `src/router.ts` lui passe l'historique du navigateur, les tests un historique en mémoire (`app-router.test.tsx`).
- **Locale** (vocabulaire **Locale** dans `CONTEXT.md`, [ADR 0011](../../docs/adr/0011-locale-par-prefixe-d-url-paraglide.md)) : `fr` et `en`. **Tout texte d'UI passe par les messages** : texte en JSX, `aria-label`, `aria-valuetext`, `title`, `alt`, `placeholder`, toasts, titre d'onglet ; jamais une chaîne française ou anglaise en dur (seuls les noms propres, les nombres et la ponctuation ; la règle `typomaniac/no-hardcoded-ui-text` le vérifie, voir le `CLAUDE.md` racine). Les catalogues sont `messages/en.json` et `messages/fr.json` (Paraglide JS 2, `en` en base), clés anglaises en snake_case préfixées par zone (`sidebar_nav_play`) ; un message qui se compte passe par une variante `plural` (voir `sidebar_friend_requests`), jamais par un `count === 1`. Un message dont une entrée est un élément (lien de Handle, nom en gras) passe par `withSlots` (`src/locale/message-slots.ts`, `withSlots((marks) => m.activity_friendship(marks, { locale }), { friend: <HandleLink … />, other: … })`) : l'ordre des mots reste celui du message dans chaque Locale, jamais une phrase recollée de morceaux. `catalog-parity.test.ts` échoue si une clé ou une variable n'existe que dans une Locale. Paraglide compile les messages dans `src/paraglide/` (généré, hors git, oxlint et oxfmt ; options dans `paraglide.options.ts`, partagées par le plugin Vite et le script `messages`, que `check-types` lance avant `tsc`). Un composant qui parle lit la Locale par `useLocale()` (`src/locale/use-locale.ts`) et la passe à chaque message, `m.sidebar_nav_play({}, { locale })` : sans elle, le React Compiler garde le texte mémoïsé après une bascule. **Jamais `Intl` avec une Locale en dur** : nombres, dates, durées relatives, pluriels et ordinaux viennent des formatters de `src/locale/formats.ts` (`numberFormat`, `dateFormat`, `relativeTimeFormat`, `pluralRules`, `ordinal`, mémoïsés par Locale), appelés avec la Locale de `useLocale()` ; les tournures d'une langue (espace avant `%`, ordinaux) vivent dans les messages ou les formatters. Chaque URL commence par la Locale (`/fr/leaderboard`) : la réécriture du routeur (`rewrite` de `createAppRouter`, fonctions pures de `src/locale/locale-url.ts`) la retire avant de chercher la route et la remet sur chaque URL écrite, l'arbre des routes ne la voit jamais, et chaque URL lue pose la Locale montrée. Une URL sans préfixe (la racine, un ancien lien) est renvoyée vers la Locale retenue, sinon celle du navigateur (`browserLocale`), dès la création du routeur ; la première visite retient la Locale de son URL. Le store `useLocaleStore` (`src/stores/locale-store.ts`, persisté `typomaniac-locale` v1, calqué sur le store de Theme) tient la Locale montrée (`locale`, celle de l'URL) et celle retenue (`chosen`, que seul le sélecteur change) ; il remplace le `getLocale` de Paraglide. La bascule (`useSwitchLocale`) réécrit l'entrée d'historique sous l'autre préfixe, sans navigation ni rechargement : la page reste montée, la WebSocket et la Queue survivent. `DocumentLocale` (monté dans `RootLayout`) garde `<html lang>` ; le script inline d'`index.html` l'a posé avant React, par la même résolution (`locale-boot.test.ts`). **Interrupteur de livraison** (`englishOpen` et `deliveredLocale`, `src/locale/english-open.ts`) : en prod tout se résout en `fr`, rien n'est retenu et le sélecteur est masqué ; en dev, `/en` et le sélecteur sont ouverts pour vérifier chaque zone. Le setup des tests fixe `fr` : un test en anglais pose `useLocaleStore.setState({ locale: "en" })`.
- **État serveur** : React Query, jamais dans Zustand. Chaque ressource expose des `queryOptions()` dans `src/api/<ressource>.ts`, appels via le client Eden `api` et `unwrap` (`src/api/client.ts`) qui lève une `ApiError`. Les loaders font `context.queryClient.ensureQueryData(opts)`, les composants `useSuspenseQuery(opts)`. Exception : un élément d'appoint qui ne doit jamais faire attendre ce qui l'entoure (`RealtimeConnection`, qui lit le User ; le Face-off, la Queue, la Match proposal et le HUD du Duel, qui lisent son avatar ou son Handle ; « En ligne » de la barre latérale, qui lit les Friends par `useOnlineFriends`) lit via `useQuery` et n'affiche rien tant qu'il n'a pas de données. Après une action, invalider via les `queryKey` des `queryOptions`, jamais des clés recopiées. `defaultPreloadStaleTime: 0` : le cache est géré par Query.
- **Erreurs de l'API** : **TOUJOURS suivre le fichier d'erreurs de l'API**, `apps/api/src/lib/errors.ts` (section Erreurs de `apps/api/CLAUDE.md`). Toute erreur HTTP a le format `ApiErrorBody` (`{ error: { code, message, requestId, details? } }`) ; codes et types viennent de `api/errors` (`ERRORS`, `ErrorCode`, `ErrorDetail`, sans dépendance serveur), jamais redéclarés ni devinés. `ApiError` (`src/api/client.ts`, levée par `unwrap`, ou construite depuis `result.status` et `result.error.value` hors `unwrap`) valide le corps contre ce format et expose `code` (null si le corps n'est pas au format ou le code inconnu), `requestId`, `details`. On branche sur `error.code` (`"NOT_FOUND"`, `"TOO_MANY_REQUESTS"`…), jamais sur `error.status` ; la règle d'un refus se lit par `refusalAt(error, "/handle")`. Jamais le `message` de l'API affiché au User : le texte est écrit côté front. Seule exception, celle de l'API : `/api/auth/*` répond au format de Better Auth.
- **Connexion temps réel** (ADR 0007) : `src/stores/connection-store.ts`, la WebSocket de l'app (`api.duel`), une par onglet, ouverte par `RealtimeConnection` (monté dans `RootLayout`, lit le User via `useQuery` : il ne fait jamais attendre la page) dès qu'une Session existe, refermée à la déconnexion, rouverte seule si elle coupe (1 s, doublé à chaque échec, 8 s au plus). Elle tient la place du User (`place`, poussée par le serveur : exception à « état serveur dans React Query », qui vaut pour HTTP) et diffuse les messages (`onServerMessage`) ; `sendToServer` envoie. Le store du Duel s'y branche : `enter` / `exit` quand Duel s'affiche ou non (prendre la place : `join-queue` ou `resume-duel` ; la quitter : `leave-queue` ou `leave-duel`), `claim` pour la reprendre depuis l'écran « ouvert dans un autre onglet ». Elle tient aussi les Friends (`friends`, null jusqu'au `friends-snapshot` de chaque socket, oublié à la perte) : la Presence de chacun (`presences`, un Friend absent est hors ligne) et `requestsReceived`, que lit le badge de Friends dans la barre latérale ; `friendsAfter` applique les messages (logique pure, testée). `LiveFriendLists` (monté dans `RootLayout`) invalide `FRIEND_QUERY_KEYS` quand un message dit que les listes ont changé (`changesFriendLists` : snapshot, Friend request reçue ou partie, Friend ajouté ou retiré) ; `FriendRow` affiche la pastille sur `/friends` (`useFriendPresence`, `FriendPresence`). Et les Challenges (`challenges`, null jusqu'au `challenges-snapshot`, oublié à la perte) : `challengesAfter` (logique pure, testée) ramène chaque `expiresAt` sur l'horloge de l'onglet (`Date.now()`). `src/components/challenge/` : `ChallengeButton` (Défier, sur chaque Friend ; `challengeBlocker` dit pourquoi il est désactivé), et montés dans `RootLayout` `WaitingChallenges` (cartes fixes par-dessus la page : Challenge envoyé annulable, Challenges reçus avec les secondes qui leur restent, Accepter / Refuser), `ChallengeNotices` (toasts : refus d'envoi, Challenge envoyé refusé, expiré ou devenu impossible) et `DuelOnChallenge` : un `duel-found` hors de l'écran de Duel est un Challenge accepté, joué dans cet onglet → Duel choisi (le Run solo en cours est remplacé par un neuf), navigation vers `/`, où `DuelArea` le reprend (`resume-duel`).

À chaque t, `sidesAt` (`replay-sides.ts`) rebâtit les deux côtés par le moteur, comme le Text : `runAt` les deux Runs, `liveWpm` leur wpm, `computeScore` les deux Scores ; `RunText` les rend comme en jeu : le Run du côté choisi (`ReplayView`, Toi ou l'adversaire, `viewedSides`) avec le caret de l'autre. À la fin de la lecture, `ReplayResults` (les deux `PlayerResult` côte à côte, comme l'écran de fin du Duel : nom et chiffres dans la couleur du joueur, `tone` de `ScoreResult`, `RunResult` et `ResultStat`) prend la place des cartes et du Text. - **Types de l'API** : `import type { App } from "api"` (dépendance workspace). Même version d'`elysia` que l'API.
- **État client** : Zustand dans `src/stores/`, `create<T>()(...)`. **Jamais** de destructuring du store (`const { a, b } = useStore()`) ni d'appel sans sélecteur : le composant s'abonne alors à tout le store et re-render à chaque changement. Un sélecteur atomique par valeur (`const a = useStore((s) => s.a)`), et `useShallow` seulement si un sélecteur doit renvoyer un objet ou un tableau.
- **Composants SRC (Single Responsibility Component)** : **toujours**. Un composant = une responsabilité (afficher, orchestrer, gérer un état ou un effet), pour rester refactorable. Dès qu'un composant mélange plusieurs rôles ou qu'un bloc de JSX a sa propre logique, l'extraire dans son propre composant (ou la logique dans un hook). Un composant par fichier.
- **Env** : toute variable `VITE_*` passe par le schéma de `src/env.ts` (voir `.env.example`).
- **Imports** : toujours via l'alias `@/` (→ `src/`, résolu par `resolve.tsconfigPaths` de Vite), jamais en relatif.

Cas typique : les `cva` exportés à côté du composant partent dans `<nom>-variants.ts` (voir `button-variants.ts`) à cause de `react/only-export-components`.

## Quand tu as fini d'éditer du code

Lancer React Doctor avant de rendre la main, en plus de `bun run check` (lancé par le hook Stop). Corrige ce qu'il remonte, puis relance jusqu'à ce qu'il ne reste rien, ou seulement des points que tu signales explicitement à l'utilisateur.

Depuis `apps/frontend` :

```sh
bunx react-doctor@latest . -y --no-telemetry --verbose
```

- Corriger la cause dans le code : ne jamais toucher à la config react-doctor ni supprimer une règle pour faire taire un diagnostic.
- Si un fix demande une décision d'API, d'UX ou d'architecture : s'arrêter et demander.
- Pour comprendre une règle : `bunx react-doctor@latest why <fichier>:<ligne>`.
