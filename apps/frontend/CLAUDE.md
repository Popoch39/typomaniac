# apps/frontend

Front React 19 + Vite 8 (React Compiler via `@rolldown/plugin-babel`). Point d'entrée : `src/main.tsx`.

## Skill obligatoire

**Avant de créer, modifier ou relire un composant, un hook ou tout code React**, invoquer le skill `vercel-react-best-practices` et appliquer ses règles. Pas d'exception pour les petites modifications.

## Architecture

- **Routing** : TanStack Router en file-based (`src/routes/`, plugin Vite, `autoCodeSplitting`). `src/routeTree.gen.ts` est généré (ignoré par oxlint/oxfmt), ne pas l'éditer. Un fichier de route ne déclare que `Route` ; ses composants vivent dans `src/pages/` (sinon `react/only-export-components` casse, et exporter le composant depuis la route désactive le code-splitting).
- **État serveur** : React Query, jamais dans Zustand. Chaque ressource expose des `queryOptions()` dans `src/api/<ressource>.ts`, appels via le client Eden `api` et `unwrap` (`src/api/client.ts`) qui lève une `ApiError`. Les loaders font `context.queryClient.ensureQueryData(opts)`, les composants `useSuspenseQuery(opts)`. Exception : un élément d'appoint qui ne doit jamais faire attendre ce qui l'entoure (`RealtimeConnection`, qui lit le User) lit via `useQuery` et n'affiche rien tant qu'il n'a pas de données. Après une action, invalider via les `queryKey` des `queryOptions`, jamais des clés recopiées. `defaultPreloadStaleTime: 0` : le cache est géré par Query.
- **Connexion temps réel** (ADR 0007) : `src/stores/connection-store.ts`, la WebSocket de l'app (`api.duel`), une par onglet, ouverte par `RealtimeConnection` (monté dans `RootLayout`, lit le User via `useQuery` : il ne fait jamais attendre la page) dès qu'une Session existe, refermée à la déconnexion, rouverte seule si elle coupe (1 s, doublé à chaque échec, 8 s au plus). Elle tient la place du User (`place`, poussée par le serveur : exception à « état serveur dans React Query », qui vaut pour HTTP) et diffuse les messages (`onServerMessage`) ; `sendToServer` envoie. Le store du Duel s'y branche : `enter` / `exit` quand Duel s'affiche ou non (prendre la place : `join-queue` ou `resume-duel` ; la quitter : `leave-queue` ou `leave-duel`), `claim` pour la reprendre depuis l'écran « ouvert dans un autre onglet ». Elle tient aussi les Friends (`friends`, null jusqu'au `friends-snapshot` de chaque socket, oublié à la perte) : la Presence de chacun (`presences`, un Friend absent est hors ligne) et `requestsReceived`, que lit le badge du header ; `friendsAfter` applique les messages (logique pure, testée). `LiveFriendLists` (monté dans `RootLayout`) invalide `FRIEND_QUERY_KEYS` quand un message dit que les listes ont changé (`changesFriendLists` : snapshot, Friend request reçue ou partie, Friend ajouté ou retiré) ; `FriendPresence` affiche la pastille sur `/friends`. Et les Challenges (`challenges`, null jusqu'au `challenges-snapshot`, oublié à la perte) : `challengesAfter` (logique pure, testée) ramène chaque `expiresAt` sur l'horloge de l'onglet (`Date.now()`). `src/components/challenge/` : `ChallengeButton` (Défier, sur chaque Friend ; `challengeBlocker` dit pourquoi il est désactivé), et montés dans `RootLayout` `WaitingChallenges` (cartes fixes par-dessus la page : Challenge envoyé annulable, Challenges reçus avec les secondes qui leur restent, Accepter / Refuser), `ChallengeNotices` (toasts : refus d'envoi, Challenge envoyé refusé, expiré ou devenu impossible) et `DuelOnChallenge` : un `duel-found` hors de l'écran de Duel est un Challenge accepté, joué dans cet onglet → Duel choisi (le Run solo en cours est remplacé par un neuf), navigation vers `/`, où `DuelArea` le reprend (`resume-duel`).
- **Replay** (`src/components/replay/`, route `/duels/$duelId`, fichier `duels_.$duelId.tsx` pour ne pas s'imbriquer dans `/duels`) : entièrement côté client, sans le store du Duel ni la WebSocket. `replay-clock.ts` (logique pure, testée) tient le temps de lecture t, play / pause, le seek et la vitesse (0,5×, 1×, 2×) ; `useReplayClock` le fait avancer à chaque frame sur l'horloge injectée (`ClockContext`). À chaque t, `runAt` du moteur rebâtit les deux Runs et `computeScore` les deux Scores, rendus par `RunText` comme en jeu : le Run du côté choisi (`ReplayView`, Toi ou l'adversaire, `viewedSides`) avec le caret de l'autre. La couleur suit le joueur, jamais le Run affiché (`RunTone` : Toi en `caret`, l'adversaire en `opponent-caret`, caret, Burst, choix du picker) ; `ReplayTextTitle` et la teinte du Text disent quel Run s'affiche. Le caret de l'autre joueur porte son initiale (`RunCaret` `label`), en Replay comme en Duel live. Un Duel terminé par Forfeit se rejoue jusqu'au Forfeit seulement (`replayDuration` : fin moins début ; le serveur n'accepte aucun Keystroke après), avec « <nom> : abandon à N s » sous la barre de temps (`replayForfeit` : celui qui n'a pas gagné, et quand ; affiché par `ReplayForfeitMarker`). Adversaire supprimé (`opponent` null) : le seul Run du User, sans caret adverse ni toggle, « User supprimé » en en-tête. On y arrive depuis la Duel history, ou depuis l'écran de fin du Duel (`DuelEnded`) : « Revoir » (`ReplayDuelLink`), affiché seulement si `duel-ended` porte un `duelId` (null quand le serveur n'a pas pu écrire le Duel).
- **Duel chart** (`src/components/duel-chart/`) : une ligne de la Duel history se déplie (une seule à la fois) sur `DuelDetails`, qui lit le Duel par `replayedDuelQueryOptions` (cache partagé avec le Replay) : `DuelChart`, `ReplayResults` et « Revoir ». L'écran de fin du Duel (`DuelEnded`) montre aussi le `DuelChart` quand `duel-ended` porte un `duelId` (`WrittenDuelChart`, même query options, chargé en `lazy` pour garder recharts hors du bundle de l'accueil). `duelChartRows` (logique pure, testée) calcule les deux timelines via `computeTimeline` du moteur, arrêtées au Forfeit. `src/components/ui/chart.tsx` (shadcn charts, recharts) est réécrit à minima : chaque série porte sa couleur en token du thème (`var(--caret)`, `var(--opponent-caret)`), sans `ChartStyle`.
- **Stats** (`src/components/profile/`) : sur `/profile`, sous le réglage du Handle, `ProfileStats` lit `profileQueryOptions(handle)` (`src/api/profile.ts`, chargé par le loader de la route) et affiche `StatsTiles` (Duels, wpm moyen et meilleur, accuracy moyenne, meilleurs Score et Combo) et `StatsRecord` (bilan, taux de victoire), puis `ProfileProgression` : sélecteur de fenêtre (`SettingGroup` en pilules, 50 / 200 / tous, état local posé en `startTransition`, dans la clé de `profileQueryOptions(handle, window)` ; tuiles et bilan lisent toujours la fenêtre 50) et quatre `ProgressionChart` (wpm, raw, accuracy, consistency : un point par Duel, moyenne glissante sur 10 Duels calculée par `progressionRows`, logique pure testée ; tooltip avec la date ; tout en accent, seul le User y figure), ou un `EmptyState` sans Duel. Chargement : `ProfileStatsSkeleton`, `ProgressionChartsSkeleton`. Sans Handle, pas de Stats. Dans son propre `Suspense` : un nouveau Handle relit les Stats sans faire attendre le formulaire. `/profile` renvoie vers son Profile public.
- **Profile** (route `/u/$handle`, `UserProfilePage`) : le Profile de tout User, vu par un User connecté, quelle que soit la casse de l'URL (`profileQueryOptions` met le Handle en minuscules, clé comprise) : `ProfileHeader` (avatar, Handle tel que l'API l'écrit, `ProfileRank` : badge et `rankLabel` « Or II · 42 TP » ou Placements restants, rien sans Rating) et le même `ProfileStats` (`empty` : `OwnProfileEmpty`, invitation à jouer sur `/profile` ; `UserProfileEmpty`, simple constat ici ; `pendingComponent` : `UserProfilePendingPage`). Jamais de Duel history, de Duel chart ni de Replay. Chaque Handle d'un autre User y mène par `HandleLink` (`src/components/handle/`) : recherche, Friends, Friend requests (via `UserRow`), et pour un adversaire `OpponentHandle` (« User supprimé » sans lien) dans la Duel history, l'en-tête du Replay et la légende du Duel chart. Sur une ligne de la Duel history, le bouton de dépliage s'étend sur toute la ligne (`after:absolute`) et le lien passe au-dessus (`relative z-10`) : un lien ne va jamais dans un bouton. Un Visitor voit `SignInInvitation` (rien n'est chargé) ; un Handle inconnu ou abandonné (404, changé en `notFound()` par le loader) mène à `UserProfileNotFoundPage` (`notFoundComponent`) ; toute autre erreur reste une erreur.
- **Activity** (`src/components/activity/`) : sur `/friends`, `FriendsOverview` place `ActivityColumn` à côté des listes (deux colonnes en `lg`). Elle lit `activityQueryOptions` (`src/api/activity.ts`, préchargé sans attendre par le loader) dans son propre `Suspense` (`ActivitySkeleton`, aussi dans `FriendsPendingPage`) : une ligne par Activity (`DuelActivityItem`, `FriendshipActivityItem` sur `ActivityRow` : avatar du Friend, Handles en `HandleLink`, wpm, abandon, heure relative par `relativeTime`, logique pure testée, depuis l'heure de lecture). Vide : `ActivityEmpty` (focus sur la recherche). Sa clé est dans `FRIEND_QUERY_KEYS` : un Friend ajouté ou retiré la relit. En direct : `LiveActivity` (monté dans `RootLayout`) met chaque `activity-added` en tête du cache (`withActivity`, `src/lib/activity-feed.ts`, logique pure testée : une fois par id, 50 au plus), sans toucher un cache pas encore lu. L'arrivée en ligne d'un Friend (`friend-arrived`, jamais dans la lecture) va dans `arrivals` du store de connexion (`arrivalsAfter`, gardé à travers une perte, oublié au rechargement ou à la déconnexion), fusionnée à l'affichage par `feedItems` (`ArrivalActivityItem`).
- **Badges de Tier** (`src/components/tier/`, vocabulaire Emblem / Ornament / Blason dans `CONTEXT.md`, maquette « Paliers de rang » `A2 · Blason revu`) : `TierSprite`, une seule sprite SVG montée une fois dans `RootLayout` (hors flux, jamais `display: none`, qui perdrait les dégradés) : dégradés et formes partagées (`TierSpriteDefs` : métal, métal sombre, lueur par Tier, feu, feuille, plume, flamme, étoile, étincelle), un symbole Emblem (`TierEmblemSymbols`) et un symbole Ornament (`TierOrnamentSymbols`, avec lauriers, ailes et ruban en symboles à part) par Tier, sur la grille 120 × 120 de la maquette. Peinture en attributs (`tier-sprite-paint.ts` : ids préfixés `tier-`, couleurs, jeux d'attributs), sans Tailwind ni feuille de style ; les couleurs du Maniac sont fixées depuis la marque (#ff8a65), elles ne suivent pas un changement d'accent. Les composants ne font que pointer dessus (`<use href>`) : pas d'id dupliqué. `TierEmblem` (cadré sur `30 28 60 60`, remplit la boîte de l'appelant), `TierOrnament` (déborde de sa boîte), `TierBlason` (l'Ornament puis l'Emblem, `data-tier-blason`), tous `aria-hidden`. `TierBadge` (`standing` du paquet `ranked` : Fer à Diamant, Divisions IV à I, puis Maniac ; `size` `md` : l'Emblem, `lg` : le Blason), reconnaissable sans la couleur : un Emblem par Tier, la Division en barrettes (`TierDivisionBars`, une pour IV, quatre pour I, aucune en Maniac), couleur du texte en token `tier-*` (Maniac suit `--brand`). Les lecteurs d'écran lisent « Or II » (`standingName`, `sr-only`). Le Blason n'apparaît qu'au rang du Profile, à la révélation du rang, au changement de TP et dans la célébration de montée ; partout ailleurs (puces, Match proposal, Face-off, Stake, bandeau de promotion), l'Emblem seul.
- **Queue** (`DuelQueue`, maquette « Lobby » du style Social) : deux colonnes 2/3 – 1/3. `QueueSearch` : `QueueRing` (avatar du User lu par `useQuery(meQueryOptions)`, arc accent `animate-queue-arc` et halo pointillé `animate-queue-halo` en sens inverse, sous `motion-safe`), « Duel classé · 30 s · anglais », `QueueWait` (temps d'attente depuis `joinedAt`, `useQueueElapsed` ; Estimated wait et nombre dans la Queue, libellés par `src/lib/queue-wait.ts`, logique pure testée), Annuler. `queue-status` alimente `queue` de la phase `queued` du store du Duel (`QueueView`, `joinedAt` ramené sur l'horloge de l'onglet comme `startsAt` ; null jusqu'au premier). `QueueFriends` : les Friends `online` avec `ChallengeButton` (on reste dans la Queue ; une Match proposal annule le Challenge côté serveur), sans jamais faire attendre la recherche.

Prévenir un User qui regarde ailleurs (`MatchProposal`) : `useProposalArrival` joue une fois le son `proposal` (moteur du Face-off, muet si le Face-off l'est) et envoie « Adversaire trouvé » en notification système si l'onglet est caché et la permission accordée ; rien pour une proposal revenue déjà répondue. `useBlinkingTitle` fait clignoter le titre d'onglet (`PROPOSAL_TAB_TITLE`) en `pending`, l'original revient ensuite ou au démontage. GSAP : `tierUpTimeline` (halo qui s'ouvre, emblème qui atterrit en `back.out`, détails qui montent, puis halo qui respire), jouée une fois au montage par `useTierUpTimeline` (`useGSAP`, scope sur la célébration), rien sous `prefers-reduced-motion`. Son `rank-up` (fanfare en arpège, `face-off-synth.ts`) joué une fois par `useTierUpSound` sur le moteur du Face-off, muet si le Face-off l'est. Jamais le MMR.
- **Shell** (`RootLayout`) : conteneur 1280px (`max-w-7xl`), header `BrandMark` (lien vers `/`), `NavPills` (Jouer, Classement, Duels, Friends, Profil, Thèmes ; Duels, Friends et Profil seulement avec une Session), chip du User à droite (`UserMenu`, avec `RankChip` (`src/components/tier/`) sous le Handle : emblème et `rankLabel`, d'après `rank` de `/me` ; `LiveRank`, monté dans `RootLayout`, invalide `meQueryOptions` à chaque `duel-ended` dont `ranked` n'est pas null). `/themes` n'est encore qu'un `EmptyState` « bientôt ». `/health` reste routé mais hors de la nav.
- **Classement** (route `/leaderboard`, `src/components/leaderboard/`) : `LeaderboardList` lit `leaderboardQueryOptions` (`src/api/leaderboard.ts`, chargé par le loader) : une `LeaderboardRow` par User (place, avatar, `HandleLink`, `RankChip`), celle du lecteur mise en avant (`aria-current`, « Toi »), ajoutée sous la liste quand il est plus bas que les 100 premiers. Vide : `LeaderboardEmpty` (lien Jouer) ; chargement : `LeaderboardSkeleton` (`LeaderboardPendingPage`) ; un Visitor voit `SignInInvitation` (titre et raison en props, partagé avec le Profile).
- **Types de l'API** : `import type { App } from "api"` (dépendance workspace). Même version d'`elysia` que l'API.
- **État client** : Zustand dans `src/stores/`, `create<T>()(...)`. **Jamais** de destructuring du store (`const { a, b } = useStore()`) ni d'appel sans sélecteur : le composant s'abonne alors à tout le store et re-render à chaque changement. Un sélecteur atomique par valeur (`const a = useStore((s) => s.a)`), et `useShallow` seulement si un sélecteur doit renvoyer un objet ou un tableau.
- **Composants SRC (Single Responsibility Component)** : **toujours**. Un composant = une responsabilité (afficher, orchestrer, gérer un état ou un effet), pour rester refactorable. Dès qu'un composant mélange plusieurs rôles ou qu'un bloc de JSX a sa propre logique, l'extraire dans son propre composant (ou la logique dans un hook). Un composant par fichier.
- **Env** : toute variable `VITE_*` passe par le schéma de `src/env.ts` (voir `.env.example`).
- **Imports** : toujours via l'alias `@/` (→ `src/`, résolu par `resolve.tsconfigPaths` de Vite), jamais en relatif.

## UI : Tailwind v4 + shadcn/ui

- Config dans `components.json` : style `base-lyra` (primitives **Base UI**, pas Radix), couleur `neutral`, icônes `lucide-react` (le preset impose phosphor : toujours `lucide`). Fusion de classes via le paquet `cn` (officiel shadcn, remplace `clsx` + `tailwind-merge`) : `import { cn } from "cn"`. Le thème (variables CSS, polices Onest et Martian Mono via `@fontsource-variable`) vit dans `src/index.css`.
- Ajouter un composant : `bunx shadcn@latest add <nom>` depuis `apps/frontend`. Le code généré dans `src/components/ui/` appartient au repo : le corriger jusqu'à ce qu'il passe `bun run check` et react-doctor, sans jamais l'exclure du lint. Cas typique : les `cva` exportés à côté du composant partent dans `<nom>-variants.ts` (voir `button-variants.ts`) à cause de `react/only-export-components`.
- **États de chargement, vide, erreur** (`src/components/ui/`) : jamais de texte « Chargement… ». Un chargement montre des `Skeleton` à la forme du contenu dans une `LoadingRegion` (`<output>` avec `aria-label`, ce que lisent les lecteurs d'écran et les tests) ; une liste vide un `EmptyState` (raison + action) ; une erreur un `ErrorState` (ce qui se passe, ce que ça coûte, une sortie). Ex. : `DuelHistorySkeleton` (aussi `pendingComponent` de `/duels`), `DuelDetailsSkeleton`, `DuelHistoryEmpty`, `UserRowsSkeleton` (`FriendsPendingPage`, recherche), `FriendsEmpty` (focus sur la recherche), `ReplayErrorPage`, `UserProfileNotFoundPage`.
- **Avatar d'un User** : toujours `UserAvatar` (`src/components/user-avatar/`, `handle`, `image`, `ornament`, `size`, `className`, `fallbackClassName` pour le style des initiales) : l'image, sinon les initiales du Handle. `ornament` (le Tier résolu par l'API, `ornament` de `/me` et du Profile) pose `TierOrnament` derrière l'avatar (`data-ornament`, `-z-10` dans l'Avatar `isolate`), centré, deux fois sa taille, `pointer-events-none`, hors flux ; jamais en `size="sm"`. Le texte voisin qu'il déborde passe au-dessus (`relative`). Le header (`UserMenu`) et `ProfileHeader` le passent. Jamais `AvatarImage` + `AvatarFallback` ailleurs que dans lui.
- Un lien stylé en bouton : `<Button nativeButton={false} render={<Link to="…" />}>` (API `render` de Base UI, pas `asChild`).
- **Thème** : style Social, sombre uniquement (pas de mode clair, pas de variante `dark:`). `src/index.css` pose les tokens (`--ink`, `--surface`, `--surface-2`, `--text`, `--text-secondary`, `--faint`, `--opponent`, `--tier-*`, `--win` pour la marque d'un Duel gagné) et remappe dessus les variables shadcn. L’accent est **une seule** variable, `--brand` : `primary`, `ring`, `caret`, `chart-1` et `tier-maniac` en dérivent ; ne jamais coder une couleur d’accent en dur (seule exception, voulue par le ticket #89 : le métal du Maniac dans la sprite des Tiers, fixé depuis #ff8a65) (utiliser `primary`, `brand` ou `caret`). UI en Onest (`font-sans`), texte à taper et chiffres en Martian Mono (`font-mono`, avec `tabular-nums`). Cartes `rounded-card` (28px), avatars squircle (`rounded-[33%]`), boutons 44px min (toutes les tailles de `button-variants.ts`). `index.html` peint le fond encre avant le CSS (pas de flash).

- **Desktop uniquement** ([ADR 0009](../../docs/adr/0009-desktop-uniquement.md)) : pas de mise en page mobile, pas de variantes `sm:`/`md:` pour replier un écran. Sous 1024 px, l'app entière cède la place à l'écran « passe sur ordinateur ». Concevoir pour 1280 px et plus.

## Quand tu as fini d'éditer du code

Lancer React Doctor avant de rendre la main, en plus de `bun run check` (lancé par le hook Stop). Corrige ce qu'il remonte, puis relance jusqu'à ce qu'il ne reste rien, ou seulement des points que tu signales explicitement à l'utilisateur.

Depuis `apps/frontend` :

```sh
bunx react-doctor@latest . -y --no-telemetry --verbose
```

- Corriger la cause dans le code : ne jamais toucher à la config react-doctor ni supprimer une règle pour faire taire un diagnostic.
- Si un fix demande une décision d'API, d'UX ou d'architecture : s'arrêter et demander.
- Pour comprendre une règle : `bunx react-doctor@latest why <fichier>:<ligne>`.
